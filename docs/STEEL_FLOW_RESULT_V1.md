# 钢铁合成投入传递结果包 v1

平台入口：保存与导出 → 导出、备份与恢复 → 原生投入传递结果（工程测试）。本入口只读，不改当前项目、评分、冻结检验或历史库，也不启动原生模型。

生成器为 `scripts/gcam_positive_output_smoke.py`。八次原生运行及数值核对完成后，除原有 `results.json` 外，输出可携带的 `result-bundle.json`。旧版仅有results.json、缺少市场需求和固定需求字段的结果不能自动升格；须用新程序重新运行。原始debug、日志仍保留在生成器结果目录，结果包不包含或认证这些原始文件。

## 文件约定

独立封套，不改变Project 1.0.0、CIB运行归档或钢铁覆盖请求。最多16 MiB，严格七字段：

|字段|要求|
|---|---|
|format|`scenario-workbench.steel-input-flow-result`|
|version|1|
|testOnly|true|
|reportJson|原始报告JSON文本，UTF-8字符串|
|reportSha256|对reportJson精确UTF-8字节做SHA256|
|caseJson|可选的原CIB关联留档精确文本；未关联时为null|
|caseSha256|对caseJson精确UTF-8字节做SHA256；未关联时为null|

保留文本而不跨语言重序列化参与哈希，避免Python的2.0与JavaScript的2造成误判。关联留档内含中文及文件开头BOM时，其字节均保留；解析CIB留档时才去除开头BOM。关联文件仍限8 MiB。报告中的linkedCaseSHA256须与caseSha256相同。

报告须是`synthetic-positive-output-steel-smoke`、status=passed、nativeRuns=8、testOnly=true；fullGCAMChina、policyEffectEvaluated、researchMappingApproved必须均为false。程序版本声明须为已测试的GCAM8.2/gcam-v8.2；该声明和程序哈希不构成来源认证。

报告target为钢铁2030年新增技术、EJ/Mt能源系数；原值必须为正、改后可为0。关联模式target须与留档逐字段一致；caseCheck按独立CIB核验器摘要格式匹配。无关联模式不允许附带孤立的复核摘要或关联哈希。

## 复核内容

八次记录必须恰为两种寿命结构×基准/改后×目标/对照地区，无重复或缺项，exitCode=0。同一基准或改后变体的XML哈希须相同；关联模式改后XML哈希须对应留档XML。每次保留2030、2035有序快照，逐批次产出、能源投入、系数与材料投入，以及总产出、总能源/材料投入、固定钢铁需求、市场能源/材料需求。

重新检查逐批次`能源投入=产出×系数`、材料投入=产出×3，逐批次之和对应总量、市场需求，产出对应固定需求；基准与改后批次产出及材料不变，系数改变仅作用于目标地区2030批次，对照地区能源不变。两个结构的总产出固定为1、2 Mt，目标2030批次的份额分别为2030的100%/2035的0%、两年的50%。按批次权重重新生成八行摘要，逐字段比对原摘要。容差为相对5e-6、绝对1e-10，适配原生debug有效位数。

关联模式另外调用完整CIB留档核验器，重算所选冻结组合，核对因素、状态、完整组合、人工设定、目标与覆盖XML；不重新认证全空间解数，不重新读取原模型输入，不代表当前项目已复算。

## 查看与独立核验

浏览器导入后显示完整冻结情景、关联因素和未经审定的人工说明，列出八行对照，支持下载HTML摘要、取回结果包及原关联留档。展示能源投入以PJ计，EJ×1000=PJ；Mt为百万吨。只改展示单位，保留原始EJ数值。

```powershell
node scripts/check-steel-flow-result.mjs result-bundle.json
```

Node22以上，无第三方运行时依赖；校验失败返回非零码。命令行和页面共用校验器。页面异步导入采用代次控制；换文件立即清空旧结果，离开页面清理，失败不保留可下载的旧成功记录。

页面通过措辞固定为“包内一致性核验通过”，不是重新运行GCAM或结果真实性认证。哈希不是数字签名；有意一致改写整包内容仍可能通过内部一致性检查。该测试固定需求、固定价格、单工艺、合成寿命，未校准实际省级行业；2035输出不是2035年CIB检验。不能把5%/2.5%当成真实政策效果。
