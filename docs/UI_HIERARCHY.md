# 界面层次调整 · 2026-11-16

针对现有项目中辅助内容占屏、年度方案与全空间检验混淆、下载入口过深的问题，调整呈现顺序和可展开区域；计算方法、项目格式与评分未改变。

- 因素页：已有选择时收起参考框架与示例项目；未选择因素时保持起点可见。没有分类目录的自定义项目不再误报自动载入失败。
- 检验页：本次结果下载位于摘要之后；单独年度方案检验标明可选，未选齐时默认收起，显示待选数量。补选和重绘保留展开状态；摘要的“查看原因”自动打开对应区域。完整年度方案首次进入仍展开。
- 稳健性：方案管理与批量扫描默认收起；方案数量与读取失败可在标题识别。扫描任务启动后，进度和停止按钮在折叠区域外保持可见。

验收：356 项自动测试，355 通过、1 项真实服务测试跳过、0 失败。构建完成。Chrome 离线版与本机 HTTP 源码页均通过 ui-hierarchy-browser.cjs，覆盖键盘展开、补选重绘、完整求解及实际 JSON 下载、查看原因、扫描收起后进度可见；1024px 布局入口可见。joint-plans-browser.cjs 与 conditioned-browser.cjs 通过，包含保存、备份迁移、比较、给定条件和窄屏检查。未开展真人可用性测试，也不等于完成全面无障碍认证。

同一 5 因素项目、1440×1000 视口的截图：因素页全页高度 1653→1347；结果页 2224→2022；稳健性页 1444→1000（后者为截图视口下限）。这些是默认内容占屏变化，不代表操作效率提升的实验结论。

后续优先观察：首次用户能否区分“查找全部组合”与“检验自己的方案”；是否会使用方案卡下方的表格；关系图选择器是否需要搜索或分组。当前关系图是判断的主要入口，尚不因占屏就隐藏。短定义适合就地提示，长依据适合抽屉；连续填写与计算选项采用可展开区域，避免反复弹窗打断任务。
