2026年11月15日统一版。平台包标识0.2.0，独立CIB算法包0.1.0。对应具体文件与代码提交以交付包中的版本清单及文件哈希为准；登记名称、登记版本、权属及申请主体仍须确认。本手册不表示软著已提交或论文已投稿。

1. 启动与保存位置

先将整个交付ZIP解压到一个新文件夹，再打开“00_打开这里.html”，从中进入“平台.html”。离线平台无需安装程序、不上传项目数据；源码index.html则需要本地服务。使用Chrome或Edge等现代浏览器。独立算法包需要Node22以上；原生工程实验另需Python、GCAM8.2和JRE，详见其随包说明。

项目自动保存在当前浏览器及其本地文件环境中，不会自动同步到其他电脑或浏览器。更换文件位置、浏览器配置、清缓存前先下载备份；不同离线HTML文件不应假定共用存储。不要在无痕窗口中长期保存唯一副本。

2. 第一次完整检验：使用随包合成示例

  1. 进入“保存与导出 → 导出、备份与恢复”，在“从 JSON 备份恢复”选择随包的“示例/01_双因素项目.json”。确认替换前先备份原工作。
  2. 进入“检验与结果”，年份选2030。展开检验设置，核对A→B与B→A两份判断都已选用；若尚未采用，则分别选择对应判断。
  3. 点击“开始检验”或“重新检验”。该示例应得到2种自洽组合：A0/B0、A1/B1。示例状态、评分和地区都是测试假设，没有真实政策含义。
  4. 查看成立组合及支持分，下载“本次结果 JSON”。随后进入“保存与导出”，填写“检验记录名称”，点击“保存为检验记录”。
  5. 下载当前项目、历史库等所需备份；在另一个空白浏览器环境恢复，重新采用评分并检验，核对完整情景成员一致。历史归档用于追溯当时输入，不自动成为当前检验。

随包另有零解/锁定、给定条件和缺分示例。给定条件是会话设定，导入项目后须按示例说明显式选择；项目JSON不等于运行归档，独立包请求JSON也不能当项目恢复文件。

3. 建立研究范围、因素和年度方案

在“开始研究”确定地区与年份。地图点选先预览，确认后才写入研究范围。进入“因素与年度方案”选择描述符及状态，必要时补充定义、适用年份、地区和证据。目录分类用于组织材料，不自动成为计算变量；任意层级分类被选中也不表示已有合法聚合模型。

逐年选择每个因素的状态，检查年度状态是否完整。时间路径反映设定值随年份变化，不自动证明跨期自洽、可达性或因果响应。修改定义、评分、年份或条件后，应重新检验；不要把旧记录显示的成立数当成当前结论。

4. 录入并采用关系评分

在“关系评分”分别填写两个方向的状态对表。行是来源状态，列是目标状态。−3…+3表示抑制到促进的影响评分，0表示没关系；空白是未判，不能补成0。每个方向的适用地区、年份及证据须与研究范围对应。保存评分后到“检查评分完整性”定位缺口，采用所需判断再继续检验。

政策原文可支持政策事实或目标；两因素关系及强度需要相应研究依据。评分依据清单列出本次冻结输入实际用到的判断与引用；“已审核”记录不等于平台独立认证文献内容，方法论文也不自动成为具体关系规律证据。

5. 检验、解释与记录

“检验我的方案”检查当前年度选择；全空间检验列出所有满足本次输入的自洽组合。自洽指每个接受判定的因素，其所选状态支持分不低于任何替代状态，允许并列最大；不是最优方案、现实发生概率或政策效果证明。

查看成立配置的逐项支持分与来源，核对年度方案是否属于其中。成立数相同仍可能是不同组合，应比较具体成员。完整运算零解是一个有效计算结果；缺分、超限或取消为未完成/未定，不能写成零解。精确枚举当前上限100000个候选；状态频数只描述当前解集。

“下载本次结果 JSON”保留冻结输入及运行结果；“保存为检验记录”将归档写到本机历史库。刷新后本会话运行不自动恢复为当前已完成，必要时重新检验；输入变化不会改写旧冻结归档。

6. 给定条件与普通锁定

在“检验与结果”展开“给定条件（可选）”，为因素选择给定状态；其他因素保持“参与自洽判定”。给定因素继续影响其他因素，自身免于平衡检验。普通锁定只限制所选状态，仍需接受自身平衡检验，两种含义不能混用。

至少保留一个接受判定的因素。给定与锁定状态冲突会阻断。条件会随结果归档，但刷新或新环境恢复后须重新设置，不能只恢复项目便假定条件存在。条件与年度方案不一致时，应先调整，不能把该方案称为满足本次条件的自洽方案。

7. 单格、批量与联合改分

先完成一次检验，再进入“稳健性检验”。单格改分选择方向、状态对与新评分后重算，查看保留、新增和移出成员。批量扫描逐格作合法±1变体；它是工程探查，真实争议范围须有依据，不能把默认±1当成研究事实。停止或预算阻断时，结果只覆盖已完成部分。

联合改分逐次“加入联合改分”，至少两格后点击“联合重算并比较”。联合结果不能由各单格结果相加代替。输入使用冻结副本，不修改当前项目原判断。填写名称后“保存联合方案”，可载入重算及并排比较两份已保存方案。

联合方案最多12份、总量2MB；基线年份、地区、判断、状态或条件不同不能直接套用。刷新后先恢复原项目与条件、完成原基线检验，再载入方案重算。比较结果JSON不能替代联合方案备份。

8. 完整备份与换环境恢复

平台有三个独立保存位置。换电脑或清理浏览器前，按需要分别下载下列文件；一份“项目备份”不包含另外两份库。

9. 模型工程接口与结果回接

三个入口均在“保存与导出 → 导出、备份与恢复”。原生程序运行位于独立工具中，浏览器不会自动运行GCAM。

  1. 钢铁系数覆盖（工程测试）：选择本机钢铁XML与必要的商品单位证明，选齐地区、工艺、新增技术年份和投入项。明确选择操作及数值，核对原值与单位，确认后预览、下载XML、核验记录和请求JSON。编辑会使旧预览失效；切换页面清理已选文件。
  2. 关联CIB情景与人工设定：可选一份冻结结果中的完整自洽组合，再选输入型因素，填写人工参数设定说明；地区编码不同时另写对应说明。年份须相同。状态不会自动换算为参数，依据仍需研究审定。可下载含完整情景和XML的关联留档，并独立重新核验、取回XML。
  3. 原生投入传递结果（工程测试）：独立程序运行后选择其result-bundle.json，页面重算八行对照，核对批次投入、固定需求、市场总量及原CIB/XML对应，显示完整情景与人工说明。可下载HTML摘要，取回结果包和关联留档。旧版只有results.json的文件须用新版程序重新生成。

“包内一致性核验通过”不表示网页重新运行了GCAM或认证了程序来源；哈希不是数字签名。当前原生实验采用合成固定需求、固定价格、单工艺及寿命结构。系数降5%、受影响批次占一半时投入降2.5%仅用于核对加权关系，不是实际省级节能预测。2035读数不表示2035年CIB已检验。完整GCAM-China、CHEER及正式研究映射尚未验收。

10. 独立CIB算法包

交付包中的cib-core目录保留0.1.0计算代码；平台与独立包目前采用各自实现，本轮不宣称合并内核。独立包请求字段为descriptors、blocks与options；项目备份、运行归档不能未经转换直接送入CLI。

node cib-core/cli.mjs 示例/01_独立包请求.json

descriptors按ID列出各自状态；blocks每项是[来源ID,目标ID,评分二维数组]，行列顺序与状态数组一致。options.fixed指定状态，mode=conditioned为给定免检，mode=locked为普通锁定；未指定fixed时默认conditioned不产生任何给定因素。成功完成退出0，包括完整零解；缺分或超限退出2且count为空；非法结构退出1。

随包请求和项目使用同一合成矩阵，期望完整成员列在“示例/示例说明.html”。独立包与平台对照只是这些输入的验证，不代表所有格式无需转换或所有功能相同。独立包源码与发布许可仍按项目权属决定，未授予自动再许可。

11. 常见问题

现象先检查什么
填过评分仍提示缺判断检查是否两个方向、全部所需状态对都填齐，地区/年份适用，所需记录已采用。不要用0填掉未知。
刷新后没有刚才结果项目与冻结历史是不同存储；查看已保存检验记录，或按原输入与条件重新检验。
恢复后找不到联合方案检查是否还保存、导入了单独的联合方案备份，而非只导入项目或比较报告。
结果看起来一样比较完整情景成员、年份及给定条件，不能只看成立数。
模型结果文件导不进选择result-bundle.json，不是原始debug.xml或旧results.json；查看版本、体积和具体核验提示。
本机保存失败先下载所需备份，记录失败提示；不要把页面暂存当成已可靠保存。
