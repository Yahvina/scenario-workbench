# CIB情景与钢铁参数关联留档 v1

入口：保存与导出 → 导出、备份与恢复 → 钢铁系数覆盖（工程测试）→ 关联CIB情景与人工设定（可选）。默认仍不关联，可继续独立参数工程测试。

## 关联时明确做什么

选一份本会话或已保存的冻结检验，显式选择其中一个完整自洽组合，再选其中一个输入型因素。所关联状态从完整组合读取，不允许把不同组合的状态拼起来。参数操作与数值仍由用户填写，必须说明为何采用；地区编码不同还须填写未经审定的人工对应说明。

要求检验已完成且保留了组合。前置阻断、失败、零解、错年份、缺说明和结果型/背景因素拒绝。所选新增技术年份须与冻结CIB检验年份相同；本版没有跨期转换规则。

工程参数入口先核对源XML、原值和单位，关联阶段再使用既有归档校验器及冻结矩阵复核所选组合。普通锁定和给定条件沿用原引擎语义，给定条件仍免于自身平衡判定。原始项目、评分、保存库和既有归档均不修改。

## 下载内容

关联后XML增加一条工程注记，含冻结归档、完整配置和人工设定的SHA256及关联留档文件名，参数数值保持所填操作。核验记录增加 `cibOrigin`，`cibConsistencyEvaluated: true` 仅表示所选组合已复核，**不表示重算全空间解数或审定参数映射**。

`steel-cib-case.engineering.json` 是独立容器，不修改Project1.0.0或模型参数请求v1：

|字段|内容|
|---|---|
|format / version|`scenario-workbench.steel-cib-case` / 1|
|testOnly / researchMappingApproved|始终true / false|
|cib.archive|完整冻结检验封套，含原评分、输入、结果和原假设确认|
|cib.configuration / trace|所选完整配置及按冻结输入重新计算的解释|
|cib.factor|输入型因素及所选状态的ID、标签|
|cib.assumption|用户填写的参数设定说明，kind=user-assumption、reviewStatus=unreviewed|
|cib.regionCorrespondence|CIB地区、模型地区、人工说明；字面编码相同也不表示语义对应获审|
|cib.validation|所选组合复核为true；全空间计数重算、当前项目检验、完整模型执行均为false|
|parameter|实际下载的XML、核验记录、原参数请求；原始模型XML不嵌入|
|integrity|上述对象、实际XML字节、原请求和完整负载的哈希|

对象键按字典序排列后计算JSON哈希，数组顺序保留；完整负载哈希不包含自身。哈希用于防止文件误配，不是来源身份签名。关联留档上限8 MiB，原归档仍按既有5 MiB边界检查。

改动参数、关联选择或人工说明立即清空预览并禁用下载；关联模式下修改参数需重新勾选核对。切换检验来源须重选组合和因素；迟到的生成结果不得恢复旧下载。

## 重新核验

页面中展开“核验已下载的CIB关联留档”，选JSON后核验通过即可取回同一份XML，不需要把原项目恢复为当前项目。重新选择文件立即清理旧核验；损坏、超大或过期异步读取均不能保留旧下载。

也可在Node22+、无第三方依赖的环境运行：

```powershell
node scripts/check-steel-cib-case.mjs steel-cib-case.engineering.json
node --test tests/steel-cib-link.test.mjs
```

重新核验会检查容器完整性、冻结归档、所选完整组合、人工设定、参数计算、XML与审计对应。**不会重读原模型XML、重新核验其单位来源、重新枚举全空间、检验当前项目或运行GCAM。** 下载的独立参数请求仍可用Python组件复跑数值，完整CIB关联则以此容器为准。

只有研究问题、状态、阈值、统计口径、地区对应、参数转换获得相应依据与审定后，才可能形成真实研究映射。本功能不改变当前“工程测试、未经审定”的交付性质。
