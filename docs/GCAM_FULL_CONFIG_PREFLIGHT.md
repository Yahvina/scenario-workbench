# 完整 GCAM 配置运行前核查

当前平台的钢铁接口、合成投入实验和结果包核验属于局部工程验证。它们不证明完整 GCAM-China 已校准、运行或得到可信的政策结果。

## 文件检查的范围

在原配置所在目录解释相对路径，按 `ScenarioComponents/Value` 的原顺序逐项检查文件、大小和哈希。名称可能重复；不得转成以名称为唯一键的对象后去重，否则会遗漏输入或改变覆盖顺序。

`Files` 包含输入及输出位置；不能把所有值都当成必须已经存在的输入。批处理、政策目标等辅助文件还要结合实际开关判断。组件 XML 还可能引用气候模型 INI 和 CSV；顶层文件齐全不等于运行依赖完整。

完整模型运行应使用隔离工作副本，重定向数据库、调试输出和日志，保留原配置、输入顺序及哈希。不得直接覆盖模型原目录中的输出或改写源输入。输入体积和可用内存只能辅助安排运行资源，不能据此保证收敛或推定最低内存要求。

## 通用 XML 检查不等于原生解释

实际核对的 GCAM 8.2 求解器输入在筛选表达式中使用字面 `&&`。标准 XML 解析器拒绝该写法，但原生 GCAM 在已验证的合成小模型中接受未改动的原文件。

只在副本中把它替换为 `&amp;&amp;` 后，原生程序反而报告 `Could not parse filter string`。此时退出码仍为 0，并仍出现 `All model periods solved correctly`。因此：

- 标准 XML 格式检查结果与原生加载结果分开记录；不能把前者单独当作完整模型不可运行的证明。
- 不用通用格式化或转义工具批量“修复”GCAM专用表达式。更改时须在隔离副本中核对原生语义与日志。
- 成功判定同时查看退出码、求解消息、解析及筛选错误、未求解市场、校准诊断和所需输出。出现“完成”消息并不能抵消其他错误。

上述对照仅加载原求解器并运行既有合成小模型，没有运行完整行业配置，也没有证明所有筛选分支或校准过程正确。

## 研究链路另行验收

先冻结完整模型基线，再在单一受控修改下比较结果，核对地区、技术、年份、单位、新旧批次及对照项。状态到数值的对应和幅度必须有研究依据；导出成功、文件哈希一致或合成投入按系数变化，均不替代真实研究映射。

平台导入结果包是只读核对，不执行 GCAM，不认证程序来源，也不宣布完整模型已经校准。当前完整 GCAM-China 与 CHEER 的真实研究运行仍待完成。
